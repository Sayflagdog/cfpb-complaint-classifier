# Реальные измерения от 21.10.2026

Это архив ранних опытов E1–E3. Первая нагрузочная попытка E4 находится в
`failed-E4-worker-oom/` и исключена из таблицы и графиков: второй воркер
завершился с кодом 137, что исходный оркестратор не обнаружил.
[Полная повторная матрица](../2026-10-21-final/README.md) служит основой
выводов в [основном README](../../../README.md#измерения-backpressure-и-материалы-этапа-b).

## Состав данных

- `input.csv` — 800 одинаковых синтетических текстов. Генератор находится
  в `scripts/run_backpressure_experiments.py`, SHA-256 — в `environment.json`.
- `environment.json` — версия Git, хеши исходников, входа и lock-файла на момент
  измерения. Последующие исправления оркестратора не задним числом меняют эти хеши.
- `E*/config.json` — условия конкретного опыта, версия модели, образ и баланс.
- `E*/source.csv` — каждое подтверждение и отказ/неподтверждённая публикация:
  timestamp, стабильный task_id, раздельные накопленные счётчики.
- `E*/samples.csv` — временные ряды глубины, памяти и скоростей. `phase=load` —
  первые 20 секунд, `drain` — завершение оставшегося конечного пакета.
- `E*/tasks.csv` — данные БД, время после возврата из коммита, inference,
  полное время обработки и end-to-end. API-пробы отделены `population=api`.
- `E*/api.csv` — HTTP-статус, Retry-After, ID и время каждой пробы.
- `E*/worker-*.log`, `E*/source.log` — журналы запуска и обработки.
- `summary.csv` — пересчитываемая сводка по завершённым режимам.
- `depth.png`, `rates.png`, `memory.png`, `latency.png` — графики для README.

Management API даёт дискретные показатели с задержкой: max в сводке — максимум
по наблюдениям, не точный мгновенный пик. Источник получает сигнал перегрузки
из результата публикации, а не из этих измерений. Память — рабочий набор cgroup
в MiB (usage − inactive_file), не RSS. После выхода процесса источника значение 0.

Источники E1/E3 успевают опубликовать конечный файл до участка 5–20 с; нулевая
скорость на этом участке означает завершение файла. В E2 источник активен и
его темп согласуется с обработкой. p50/p95 задач относятся ко всем 800 batch-
задачам; линии задержек — к пятиисекундным группам по времени коммита.

## Оговорки

Docker был ограничен 2 ГБ. В E3 MLflow завершился OOM в 17:24:46 UTC;
воркеры к этому времени уже загрузили модель и завершили 800 batch-задач
и 17 API-проб. Данные E3 сохранены как фактическое наблюдение, но для сравнения
без инфраструктурных сбоев был выполнен полный повтор в отдельной папке.
В первой попытке E4 один из двух воркеров завершился с кодом 137; остальные
задачи обработал выживший воркер. Поэтому этот набор не доказывает
масштабирование и сохранён только для диагностики. При повторе MLflow
штатно останавливался после загрузки модели во всех режимах, а оркестратор
проверял состояние каждого воркера. Лимит Docker остался 2 ГБ.
